# 02. 기술 스펙

---

## 1. 제약에서 나온 결정

| 대회 제약 | 기술적 귀결 |
|---|---|
| 브라우저 즉시 실행, 로딩 화면 없음 | 정적 사이트, 초기 번들 1MB 이하, 스플래시 금지 |
| 로그인·승인 없이 접근 | 인증 없음, 서버 상태 없음, 외부 API 호출 없음 |
| 심사 기간 내내 링크 생존 | 정적 호스팅 + 커스텀 도메인 없이 기본 URL |
| 현장 휴대폰 투표 | 모바일 세로 우선, 터치 타깃 44px 이상 |

**런타임 중 LLM API를 호출하지 않는다.** 비용·지연·가용성이 전부 리스크다. AI는 개발 단계와 콘텐츠 생산에만 쓴다.

## 2. 스택

- **TypeScript + Vite**
- UI는 **DOM + CSS**로 충분하다. 캔버스·게임엔진·3D 전부 불필요.
- 상태 관리는 라이브러리 없이 순수 reducer.
- 폰트는 시스템 폰트 스택. 웹폰트 다운로드 금지(로딩 지연).
- 의존성 최소. 추가할 때마다 번들 크기를 확인한다.

## 3. 아키텍처 원칙 — 코어와 UI의 완전 분리

```
src/
  core/           # 순수 함수. DOM·브라우저 API 참조 금지
    types.ts
    rng.ts        # 시드 기반 결정론적 난수 (mulberry32)
    reducer.ts    # (GameState, Action) => GameState
    scoring.ts    # 성적·평판·유입 계산
    ai.ts         # 경쟁 학원 2곳의 입찰/배치 정책
  content/
    teachers.json
    events.json
    headlines.json
  ui/
    ...
  harness/
    simulate.ts   # 헤드리스 대량 시뮬레이션 (Node에서 실행)
```

**이 분리가 프로젝트의 핵심 자산이다.** `core/`가 순수하면 UI 없이 Node에서 10만 판을 돌릴 수 있고, 그게 곧 밸런싱 하네스이자 Codex 활용 서사의 증거가 된다.

**규칙**
- `core/` 안에서 `Math.random()` 금지. 반드시 시드 RNG를 인자로 받는다.
- 같은 시드 + 같은 액션 시퀀스 = 항상 같은 결과. 리플레이와 버그 재현이 여기서 나온다.
- `core/`는 `content/`의 JSON을 데이터로만 읽는다. 로직을 JSON에 넣지 않는다.

## 4. 데이터 스키마

### 강사 카드

```json
{
  "id": "t_0142",
  "name": "가상 이름",
  "subject": "MATH",
  "teaching": 4,
  "fame": 3,
  "askingPrice": 21,
  "trait": "TOP_CLASS_SPECIALIST",
  "blurb": "한 줄 소개. 20자 이내."
}
```

### 이벤트 카드

```json
{
  "id": "e_0087",
  "trigger": { "minTurn": 2, "requires": "REPUTATION_BELOW_40" },
  "headline": "학부모 게시판, 관리 부실 성토",
  "effect": { "reputation": -3, "churn": 0.05 },
  "weight": 10
}
```

**스키마는 P1에서 확정하고 이후 변경하지 않는다.** 콘텐츠 배치 생산이 스키마에 의존하므로, 스키마가 흔들리면 생산분 전체를 버려야 한다.

## 5. 검증 도구

- **JSON 스키마 검증기**: 생성된 카드가 스키마와 값 범위를 지키는지 CI에서 자동 검사. 배치 생산물은 검증 통과 전까지 머지 금지.
- **밸런싱 하네스**: `npm run sim -- --games 100000 --seed 1`
  출력: 아키타입별 승률, 평균 턴당 입찰 성공률, 무입찰 전략 승률, 게임 길이 분포.
  01 문서 6절의 검증 질문 3개에 답하는 것이 이 도구의 목적이다.

## 6. 배포

- 정적 호스팅에 배포하고 **P2 완료 시점(8/17)에 최초 배포한다.** 마감 직전 첫 배포는 금지.
- 배포 후 확인 항목: 시크릿 창에서 열림 / 모바일에서 열림 / 새로고침 후 정상 / 로딩 화면 없음.
- 링크는 심사 기간 내내 살아 있어야 한다. 제출 후 저장소를 비공개로 돌리거나 도메인을 옮기지 않는다.

## 7. 백엔드 연동 지점 (Release Potential 대비)

지금 구현하지 않되, **인터페이스만 미리 뚫어둔다.**

```ts
// src/core/telemetry.ts
export interface ScoreSink {
  submit(run: { seed: string; archetype: string; share: number; turns: number }): Promise<void>;
}
// 기본 구현은 no-op. 이후 백엔드 SDK로 교체 가능.
```

피치에서 "랭킹과 리플레이 공유는 이 지점 하나만 갈아끼우면 붙는다"고 말할 수 있으면 충분하다. 실제 연동은 본선 이후 과제.
