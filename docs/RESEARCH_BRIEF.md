# 레퍼런스 조사 브리프 (research/reference 워크트리 전용)

이 워크트리는 **조사만** 한다. `src/` 아래 코드를 만들지 않는다.

`AGENTS.md`의 **절대 규칙 1~7은 그대로 유효**하다. 단 "작업 방식"의 트랙 A~D 경계표는
이 워크트리에 해당하지 않는다. 이 워크트리의 쓰기 가능 경로는 `docs/reference/` 하나뿐이다.

---

## 왜 조사하는가

`인계문서/01_GAME_DESIGN.md`의 규칙은 이미 확정이다. 조사는 규칙을 바꾸려는 게 아니라,
**확정된 규칙이 실제로 굴러가는지 남의 사례로 검증**하고 P2 구현 시 헛발질을 줄이려는 것이다.

따라서 산출물은 "재밌는 게임 목록"이 아니라 **우리 문서의 특정 줄에 대한 반증 또는 보강**이다.
어느 문서 몇 절에 대한 이야기인지 안 적힌 항목은 산출물에서 뺀다.

---

## 조사 축 3개

### R-1. 유사 경영 시뮬 게임
검증 대상: `01_GAME_DESIGN.md` 4절(턴 루프 7단계), 입찰 메커니즘, 1판 5분 구조.

- 인재 입찰/경매가 핵심 루프인 경영 시뮬에서 **무입찰이 지배전략이 되는 걸 뭘로 막았는지**
- 한 판 5~10분짜리 경영 시뮬의 **턴당 의사결정 개수**는 실제로 몇 개인지
- 3자 경쟁 구도에서 AI 상대를 **읽히게** 만든 방법 (07 작업 A-4 "강한 AI가 아니라 읽히는 AI")

### R-2. 모바일 세로 웹게임 UI 패턴
검증 대상: `07_ORCA_HANDOFF.md` 작업 B "타협 불가" 5개 항목.

- 로딩 화면 없이 첫 인터랙션 1.5초를 만족하는 정적 웹게임의 실제 구성
- 한 화면 숫자 7개 이하 제약 아래 **자원 3~4종을 동시에 보여주는** 레이아웃 사례
- 튜토리얼 없이 버튼 한 줄 설명만으로 규칙을 전달한 사례
- 정산 결과를 **텍스트(헤드라인) 주인공 + 숫자 보조**로 연출한 사례

### R-3. 해커톤 제출작·심사 기준
검증 대상: `04_SUBMISSION_CHECKLIST.md`.

- 게임 잼/해커톤 예선 통과작의 공통점 — 특히 Playability와 Presentation 비중
- 심사자가 **몇 초 안에** 판단하는지, 그 시간 안에 뭘 보여줘야 하는지
- 우리 체크리스트에서 **빠진 항목**이 있으면 그것만 지적

## 산출물

```
docs/reference/
├── 00_SUMMARY.md      ← 마지막에 작성. 코디네이터는 이것만 읽는다
├── 01_sim-games.md
├── 02_mobile-ui.md
└── 03_submission.md
```

각 항목은 아래 4줄 형식을 지킨다. 형식을 안 지킨 항목은 반려한다.

```
대상:            (게임/사이트/제출작 이름 + 링크)
관찰한 것:       (사실만. 해석 금지)
우리 문서 어디에: (예: 01_GAME_DESIGN.md 4절 단계 3)
그래서 뭘 하자는 건가: (제안 1줄. 반영 여부는 코디네이터가 정한다)
```

`00_SUMMARY.md`는 **한 페이지**다. 아래 3개만 쓴다.
1. 우리 설계를 **반증**하는 발견 (있으면 최우선)
2. 지금 구현 계획에 **바로 반영 가능한** 것
3. 조사했지만 **쓸 데 없다고 판단한** 것 (같은 조사 두 번 안 하려고 남긴다)

## 금지

- **실존 학원·강사·교육기업 검색 및 인용.** 게임 레퍼런스 조사이지 업계 조사가 아니다.
  검색어에 특정 학원명을 넣지 않는다. (AGENTS.md 절대규칙 1)
- **회사 내부 데이터·문서 반입.** (절대규칙 2)
- **게임 규칙·수치 수정.** 문제를 발견하면 고치지 말고 `00_SUMMARY.md` 1번에 적는다. (절대규칙 4)
- **스코프 확장 제안을 구현하는 것.** 아이디어는 `docs/PARKED.md`가 아니라 산출물에 적고 끝낸다.
- 조사에 하루 이상 쓰는 것. **8/13까지 끝낸다.** 제출 하한선은 P2 완주 웹 빌드이지 조사 보고서가 아니다.

## 완료 정의

- 실존 학원·강사·기업명이 산출물에 0건
- `research/reference` 브랜치에 커밋 (main 직접 커밋 금지)
