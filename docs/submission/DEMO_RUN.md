# 데모 대본 실행 결과 (8/21)

04 문서 3절 데모 영상 구성대로 배포본을 실제로 돌려본 기록.
스틸은 `storyboard/`에 있다 (1280×1000, 스크롤 없는 상태).

## 결론 — 촬영 설정을 먼저 정해야 한다

**1280×720(영상 표준)에서 세 화면이 전부 잘린다.** 그대로 녹화하면 데모의 핵심 장면인
"입찰에서 손이 멈추는 순간"에 제안 버튼이 프레임 밖에 있다.

| 화면 | 실제 콘텐츠 높이 | 720p에서 |
|---|---|---|
| 반 편성 | **999px** | 279px 잘림 |
| 학기 결과 | 960px | 67px 잘림 |
| 강사 입찰 | 861px | 140px 잘림 |

**대응 두 가지 중 하나를 고른다.**

1. **브라우저 줌 70%로 1280×720 창에서 녹화** — 720 ÷ 0.7 = 1029px ≥ 999px라 세 화면 모두 들어온다.
   75%(960px)는 반 편성이 39px 모자라 안 된다.
2. **창을 1280×1000으로 키워 녹화하고 편집에서 16:9로 맞춤** — 스틸은 이 설정으로 찍었다.

세로 스크롤이 한 번이라도 잡히면 "화면이 안 맞는 게임"으로 보인다. 3분짜리에서 그 인상은 회복이 안 된다.

## 실행하며 발견한 것

**① 배치는 "이동"이지 "추가"가 아니다.** 강사를 고르고 빈 자리를 누르면 그 강사가 그 자리로 옮겨간다.
이미 배치된 강사를 다시 고르면 원래 자리가 비므로, 자동 조작으로 여러 명을 채우려면
"아직 어느 슬롯에도 없는 강사"를 골라야 한다. 사람이 손으로 할 때는 문제되지 않는다.

**② 어제 브라우저 자동 플레이 수치에 이 편향이 있었다.**
`docs/JUDGE_REVIEW.md`에 인용한 실플레이 1건("남은 돈 −10, 별 0개")은 **강사를 한 명만 배치한 나쁜 판**이었다.
제대로 배치하니 3학기차에 별 2개·남은 돈 89·점유 38%가 나온다.
다만 검토서의 헤드라인 수치(승자 38.1%가 적자, 96.2%가 별 1개)는 하네스 측정이라
`planAssignments`로 정상 배치한 결과다 — **그 결론은 유효하다.** 편향된 것은 실플레이 스틸 1장뿐이다.

## 크롬 확장으로 실제 녹화 (8/21)

브라우저 확장으로 1턴을 직접 조작해 녹화했다. **`storyboard/turn1-demo.gif`** (780×499, 1.4MB, 25프레임).
클릭 위치가 주황 원으로 표시되고 하단에 진행 바가 붙는다.

담긴 흐름: 확장형 선택 → 강사 두 장 비교(별솔 12 vs 탐빛 21) → **월급 26으로 올려 제안** →
낙찰 성공 → 상위반에 글해·탐빛, 중상위반에 수해 배치 → 자습 감독 강화 선택 → 정산.
결과는 「탐빛 영입에 성공」 「상위반 강사진이 고르게 맞물렸다」, 점유 37% · 남은 돈 98 · 인기 별 2개.

**녹화하며 확인된 것**

- 이 기기 화면이 1710×1107이라 **100% 줌으로는 999px 뷰포트가 안 나온다**(창을 키워도 뷰포트 831px에서 막힌다).
  줌 **80%**로 유효 1039px를 만들어 세 화면 모두 스크롤 없이 담았다. 위에서 계산한 70%보다 여유 있게 잡았다.
- 줌아웃하면 화면 아래·오른쪽에 배경 여백이 크게 남는다. 영상에서는 **가운데를 크롭**하는 편이 낫다.
- 원본 해상도(1300×831) GIF는 4.8MB로 저장소 전체보다 커서, 780px·6fps로 줄여 1.4MB로 넣었다.
  원본은 `~/Downloads/academy-tycoon-turn1-demo.gif`에 있다.
