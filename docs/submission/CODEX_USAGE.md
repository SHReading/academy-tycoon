## 1. Codex를 어디에 사용했는가

**병렬 워크트리 4개에 각각 붙여 트랙을 동시에 굴렸다.** (`~/orca/workspaces/hackathon/`)

| 워크트리 | 맡은 일 |
|---|---|
| `codex-dev` | 시뮬레이션 코어 (types·rng·scoring·reducer·ai·headlines·events) |
| `track-ui` | 브라우저 UI 4화면과 엔진 연결 |
| `track-spec` | 착수 전 스펙 공백 감사, 밸런싱 하네스 |
| `research` | 비대칭 밸런스 레퍼런스 조사 |

메인 세션은 코드를 쓰지 않고 **코디네이터** 역할만 했다 — 스펙 정합성 유지, 태스크 분해,
트랙 간 충돌 조정, 리뷰. 이 분업은 `CLAUDE.md`와 `AGENTS.md`에 규칙으로 박아뒀다.

## 2. 어떤 기능을 구현했는가

- **결정론적 시뮬레이션 코어** — 같은 시드는 항상 같은 결과. 테스트 67건, gzip 11.1KB
- **7단계 정산 엔진** — 반별 성적 → 입시 실적 → 평판 → 지원자 → 등록 인원 → 자금 → 점유율
- **블라인드 입찰과 AI 2사** — 낙찰가가 6학기 고정비로 남는 구조
- **헤드라인 생성기** — 상황 13종을 감지해 신문 지면 형식으로 3줄 출력
- **콘텐츠 파이프라인** — 강사 40장·이벤트 20장·헤드라인 30종 + 스키마 검증기 + 실명 필터
- **밸런싱 하네스** — 10만 판을 3.7초에 돌려 판정 3개를 자동 출력

## 3. 어떤 문제를 해결했는가

**(1) 스펙 공백이 워커를 세 번 멈춰 세웠다.**
`01` 문서 4절이 정산 *순서*만 적고 계수와 함수를 안 적어놔서 코어 구현이 반복해서 막혔다.
워커가 총 16건을 물었고 전부 실제 공백이었다 — 등록 인원 정의가 통째로 없었고
`f(상위반 성적, 상위반 인원)`은 함수 자체가 없었다.
→ **착수 전에 감사 워크트리를 따로 파서 남은 구멍 53건을 한 번에 털었다**(`SPEC_GAPS.md`).
그 뒤로는 어느 트랙도 스펙 때문에 멈추지 않았다. 이번 회차의 가장 큰 교훈이다.

**(2) 규칙 사본이 두 벌로 갈라졌다.**
하네스가 코어보다 먼저 필요해서 초기 상태·시장 배포·승자 판정을 자체 구현했고,
나중에 코어가 같은 규칙을 갖게 되자 사본이 둘이 됐다.
→ 코어를 단일 출처로 만들고 하네스를 얇은 래퍼로 줄였다(227줄 → 122줄).
**같은 시드 10만 판 리포트가 리팩터 전후로 완전히 동일한 것**을 통과 기준으로 삼았다.

**(3) 밸런스가 상수 튜닝으로 안 풀렸다.**
한 아키타입 승률이 2.1%까지 내려갔다. 후보 3안을 10만 판씩 돌렸는데 셋 다 실패했고
**둘은 오히려 악화됐다** — 자금을 늘리면 더 크게 지르고 고정비로 더 빨리 죽었다.
→ 원인이 상수가 아니라 구조였다. 승자는 점유율로 정해지는데 그 아키타입은
승리 지표에 직접 곱해지는 자리에서 페널티를 맞고, 반대급부는 간접 경로로만 닿았다.
6안을 표로 만들어 사람에게 올렸고, 사람이 고른 안을 반영해 승률 14.0% / 폐원률 5.4%가 됐다.

## 4. 사람이 직접 결정한 부분은 무엇인가 ← 차별점

**규칙 설계·밸런스 판정·스코프 컷은 전부 사람이 했다.** 에이전트는 문제를 발견해서
보고하는 데까지가 역할이고 수치를 정하지 않는다 — 이 경계를 `CLAUDE.md`에 규칙으로 박았다.

| 결정 | 내용 |
|---|---|
| 수강료 0.5 | 초안대로면 매출 100/턴에 최고가 강사가 29라 "항상 최대 입찰"이 지배전략이 된다 |
| P0 종이 프로토타입 생략 | 일정상 P1 직행. 재미 검증은 플레이테스트로 몰았다 |
| 정산 계수 14건 | 정산 7건 + 감사 7건. 전부 `balance.ts` 한 파일에 모아 사람이 한 파일만 보게 했다 |
| 캐주얼 단순화 | 12슬롯 → 반 4개, 옵션 5종 → 3종, 특성 6종 → 3종. **코어 205줄이 순감소** |
| 잔액 상한 원복 | 30%→60%로 풀었더니 폐원률이 악화됐다. 되돌렸다 |
| 아키타입 밸런스 | 6안 표를 보고 지원자 배수 1.2를 선택 |
| 스코프 컷 | 멀티플레이·저장·사운드·튜토리얼 화면을 처음부터 제외하고 `PARKED.md`에 쌓았다 |

에이전트가 밸런스 변경을 제안할 때는 **(1) 관찰된 문제 (2) 원인 가설 (3) 제안값
(4) 제안값을 안 쓸 때의 결과** 순으로 쓰게 했다. 사람이 판단할 재료를 갖추게 하되
판단 자체는 넘기지 않는 구조다.
