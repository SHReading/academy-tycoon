## 8/14 — P1 완료

시뮬 코어 완주. 테스트 57건 전부 통과, typecheck 0, gzip 3.19KB, 10만 판 5.1초(예산 5분).

**막힌 것**: 01 문서 4절이 정산 순서만 적고 계수·함수를 안 적어놔서 A-2가 세 번 멈췄다.
워커가 총 16건을 물었고 전부 실제 공백이었다. 등록 인원 정의가 통째로 없었고
`f(상위반 성적, 상위반 인원)`은 함수 자체가 없었다.

**해결**: 착수 전 감사 워크트리를 따로 파서 남은 구멍을 미리 털었다(`SPEC_GAPS.md` 53건).
그 뒤로는 A-4·A-5·트랙 D가 한 번도 안 멈췄다. **구멍은 착수 시점에 하나씩 터뜨리는 것보다
미리 한 번에 찾는 게 싸다** — 이게 이번 회차의 가장 큰 교훈이다.

**두 번 데였다**: Orca 앱이 재시작되면 워크트리는 살아남지만 안의 Codex·Claude는 죽는다.
커밋만 감시하고 세션 생존은 안 봐서, 대기열이 통째로 실행되지 않은 채 반나절이 지났다.

**사람이 결정한 것**: 밸런스 승인 14건(정산 7 + 감사 7). 전부 `balance.ts` 한 파일에 모았다.

**미해결**: 판정 3 실패. SELECTIVE 승률 0.6% / 폐원률 43%.
잔액 상한을 30%→60%로 풀었더니 오히려 폐원률 50.6%로 악화됐다 — 여력을 늘리니
더 큰 부채를 지고 더 빨리 죽었다. 되돌렸다. 레퍼런스 조사(`04_asymmetry.md`)가
같은 결론을 가리킨다: Le Havre·Hegemony 둘 다 선택 지출을 위한 차입을 금지한다.

**다음**: SELECTIVE 손잡이 결정 → P2(8/17 브라우저 6턴 완주)
