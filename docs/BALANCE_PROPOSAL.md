# 정산 7단계 미정값 제안 (8/13)

01 문서 4절 단계 4는 **순서만** 적혀 있고 계수·함수가 없다. A-2(scoring) 구현이 여기서 막혔다.
05 문서에 계산 가능한 값이 있으나 "P0 전용"으로 명시돼 있어 워커가 사용을 거부했다 — 규칙대로 행동한 것이다.

## 1. 관찰된 문제

7단계 중 **5단계가 구현 불가능**하다. 상수가 없어서가 아니라 함수 자체가 없다.

| 단계 | 01 문서 표기 | 없는 것 |
|---|---|---|
| ① 반별 성적 | "반 보정 × 아키타입 보정 − 빈 슬롯 페널티" | 세 값 전부 |
| ② 입시 실적 | `f(상위반 성적, 상위반 인원)` | `f` 자체 |
| ④ 지원자 유입 | "평판 계수 × 인지도 합 계수 × 옵션 보정" | 세 계수 전부 |
| ⑤ 자금 | 운영 고정비 | 옵션 5종의 "중/대" 실제 비용 |
| ⑦ 이벤트 | — | 효과를 어느 단계 어느 값에 적용하는지 |

추가로 **등록 인원**이 어디에도 정의돼 있지 않다. ⑤와 ⑥이 등록 인원에 의존하는데 ④는 지원자까지만 만든다.
지원자 → 등록 전환(이탈률)이 통째로 빠져 있고, 이건 "기초반 배치 → 이탈률 감소"라는 반 편성 딜레마의 한 축이다.

`Academy` 타입에도 낙찰가 이력·운영 옵션·반별 배치·입찰 이력이 없어 7단계를 표현할 수 없다.

## 2. 원인 가설

01 문서는 **재미의 구조**를 적은 문서고, 수치는 6절에 "초안(가설)"로 따로 뺐다.
05 문서가 계산식을 채웠지만 P0 축약판이라는 꼬리표가 붙어 P1으로 넘어오는 경로가 없었다.
P0를 건너뛰면서 그 꼬리표를 떼는 절차도 같이 사라졌다.

## 3. 제안

**05 문서의 계산식을 P1 기준선으로 승격하고, 빠진 값만 새로 채운다.**
전부 `src/core/balance.ts` 한 파일에 모아 사람이 한 파일만 보면 되게 한다.

### 3-1. 05 문서에서 그대로 승격 (새 판단 없음)

| 항목 | 값 |
|---|---|
| 반 보정 | 상위반 ×3 / 중위반 ×1 / 기초반 ×1 |
| 빈 슬롯 페널티 | 슬롯 1개당 −2 |
| 평판 갱신 | 이전 평판 × 0.7 + 실적 × 0.3 (LEGACY만 0.8 / 0.2) |
| 지원자 배분 | 자기 지수 = 평판 + (보유 강사 인지도 합 × 2), 지원자 = 300 × (자기 지수 ÷ 3사 지수 합) |
| 옵션 비용 | 중 = 8 / 대 = 15 |
| AI 입찰 | FRANCHISE 요구연봉 ×1.2 / LEGACY ×1.1, 잔액 40% 상한 |

### 3-2. 새로 제안하는 값 (승인 필요)

| 항목 | 제안값 | 근거 |
|---|---|---|
| **입시 실적 `f`** | `상위반 성적 × min(1, 상위반 인원 ÷ 40)` | 01 문서가 인원을 인자로 넣은 이유는 "소수 정예로 실적만 뽑기"를 막기 위함. 정원 40을 못 채우면 비례 감점 |
| **아키타입 보정** (상위반 성적) | FRANCHISE 1.0 / LEGACY 1.2 / SELECTIVE 1.1 | LEGACY는 실적, FRANCHISE는 규모라는 정체성 |
| **아키타입 보정** (지원자) | FRANCHISE 1.2 / LEGACY 1.0 / SELECTIVE 0.9 | 위와 반대 방향. 셋의 승률이 40:30:30에 들어가는지는 트랙 D가 판정 |
| **이탈률** | 기본 20%, `max(5%, 20% − 기초반 성적 × 0.5%p)` | "기초반 배치 → 이탈률 감소"를 수식화. 하한 5%는 기초반 몰빵 무한 이득 방지 |
| **등록 인원** | `지원자 × (1 − 이탈률)`, 반 정원 합(200) 상한 | ⑤⑥이 요구하는 값. 정원 상한이 없으면 자금이 발산한다 |
| **옵션 보정** | 자습감독 이탈률 ×0.8 / 담임상담 성적 ×1.05·평판 +2 / 장학금 지원자 ×1.3 / 수강료인상 매출 ×1.25·지원자 ×0.85·평판 −3 | 01 문서 3단계 표의 "−20%, +5%, +30%, +25%, −15%"를 그대로 옮기고, "평판 +소폭/−"만 ±2·−3으로 수치화 |
| **이벤트 적용 시점** | ⑦에서 발동하되 효과는 **다음 턴 계산에 반영** | 정산 도중 값이 바뀌면 헤드라인과 숫자가 어긋나 화면에서 인과가 안 읽힌다 |

### 3-3. 타입 추가 (밸런스 아님, 구조)

`Academy`에 `contracts`(낙찰가별 잔여 턴), `option`(이번 턴 운영 옵션), `assignments`(반별 강사 배치), `lastBidTurn`(NO_BID_LAST_TURN 판정용)을 추가한다.
`src/core/types.ts` 변경이므로 트랙 B·C가 착수하기 전에 확정해야 한다.

## 4. 제안값을 안 쓸 때의 결과

A-2·A-3가 착수 불가 상태로 남는다. 그러면 A-4·A-5·트랙 D가 전부 막히고,
**P1(8/14)뿐 아니라 P2 하한선(8/17 브라우저 6턴 완주)도 무너진다.**
트랙 B(UI)는 더미 데이터로 화면까지는 만들 수 있으나, 붙일 엔진이 없어 완주 불가 상태로 정지한다.

제출 하한선이 P2이므로, 이 값들이 정해지지 않으면 **심사받을 수 있는 결과물 자체가 나오지 않는다.**

## 5. 되돌릴 수 있는가

있다. 전부 `src/core/balance.ts` 상수라 값 교체로 되돌아간다.
트랙 D 하네스가 10만 판을 돌려 (1) 무입찰 지배 여부 (2) 한쪽 전략 편중 (3) 아키타입 승률 40:30:30을 판정하므로,
**제안값은 시뮬이 검증할 가설이지 확정값이 아니다.** 01 문서 6절이 수치를 "초안(가설)"로 부른 것과 같은 위치다.
