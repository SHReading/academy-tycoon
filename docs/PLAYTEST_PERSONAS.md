# 플레이테스트 페르소나 5인 (P3, 8/14)

00 문서 6절의 P3는 "외부인 3명, 90초 안에 이해되는지 확인"이다. 5인으로 늘려 사전 점검한다.
**측정 대상은 재미가 아니라 이해다.** 이기는 법을 몰라도 되지만, 무엇을 누르는지는 알아야 한다.

## 왜 이 5인인가

심사는 Playability > Presentation > Originality 순으로 본다(CLAUDE.md).
따라서 (1) 규칙을 모르는 사람이 진입하는가 (2) 화면이 상황을 설명하는가 두 축에 집중한다.
장르 숙련자만 이해되는 게임은 시연에서 죽는다.

| # | 페르소나 | 배경 | 이 사람이 검증하는 것 |
|---|---|---|---|
| P1 | **처음 보는 사람** | 게임을 거의 안 한다. 모바일 퍼즐 정도만 | 튜토리얼 없이 첫 화면에서 다음 행동을 찾는가. 가장 가혹한 기준 |
| P2 | **모바일 캐주얼** | 출퇴근길에 5분짜리 게임. 긴 텍스트를 안 읽는다 | 버튼 한 줄 설명만으로 규칙이 전달되는가. 1판 5분 목표의 실사용자 |
| P3 | **경영 시뮬 숙련자** | 타이쿤·경영 시뮬을 오래 했다 | 익숙한 문법이 배신당하지 않는가. 낙찰가가 6턴 부채라는 걸 언제 눈치채는가 |
| P4 | **보드게임 경매 숙련자** | 블라인드 입찰 게임을 안다 | 입찰 정보가 충분한가. 경쟁자 예측 단서가 화면에 있는가 |
| P5 | **심사위원 시선** | 짧은 시연 영상만 본다. 직접 안 한다 | 소리 없이 화면만 봐도 무슨 일이 벌어졌는지 읽히는가. Presentation 대리 지표 |

## 각 페르소나의 행동 규칙

테스트를 재현 가능하게 하려고 행동을 고정한다. 취향이 아니라 **정해진 절차**로 돌린다.

- **P1** — 설명을 안 읽는다. 화면에서 가장 크고 색이 진한 것만 누른다. 막히면 그 지점을 기록한다
- **P2** — 각 화면에 15초만 쓴다. 15초 안에 다음 행동을 못 찾으면 실패로 적는다
- **P3** — 매 턴 최대 입찰을 시도하고 자금 흐름을 추적한다. 부채 구조를 언제 깨닫는지 기록한다
- **P4** — 입찰 전에 경쟁자 상태를 찾는다. 못 찾으면 무엇이 없는지 적는다
- **P5** — 클릭하지 않는다. 정산 화면만 보고 직전 턴에 무슨 일이 있었는지 추측한 뒤 실제와 대조한다

## 기록 양식

각 페르소나마다 아래를 채운다. **추측이 아니라 관찰만 적는다.**

```
페르소나:
막힌 지점    : 화면 / 무엇을 못 찾았나
오해한 것    : 무엇을 무엇으로 잘못 이해했나
90초 판정    : 통과 / 불통과
가장 큰 결함 : 한 줄
```

## 판정 기준

- **통과 하한**: 5인 중 4인이 튜토리얼 없이 1턴을 완료한다
- **P5는 별도**: 정산 화면만 보고 사건 3개 중 2개 이상을 맞히면 통과
- 불통과 항목은 `docs/PARKED.md`가 아니라 **즉시 수정 대상**이다. UI 결함은 P2 하한선을 갉아먹는다
